### Модалка «Запрос на мерж» (`dizzy.md`, §10 п.1)

Сверху вниз: 1) заголовок + исполнитель + ссылка (PR/папка, `head_sha`); 2) что сделано; 3) что не работает; 4) отложено; 5) риски; 6) CI / проверки (зелёный/красный, ссылки); 7) итерации («отзыв → исправлено → осталось»). Липкий низ: отзыв, чипы «кому» (по умолчанию отмечены `affected_chats`), кнопки `Отклонить` · `На доработку` · `Смержить` · `Синхронизировать`. «На доработку» и «Отклонить» без текста `disabled`. Красный CI: «Смержить» `disabled`, чекбокс «принимаю риск» включает её, отметка пишется в решение. Само решение только кладётся в outbox: статус и галочка «Смержено» появляются после «Синхронизировать». Esc закрывает модалку.

### Автомат (`bit.md`) ↔ UI

`draft → awaiting_owner → (changes_requested → awaiting_owner …) → approved → delivered → merging → merged`. Иначе: `→ rejected`; `merging → merge_failed → awaiting_owner`; `merged → reverted`. Лаунчер ставит `approved` (и `rejected` / `changes_requested`). `delivered` ставит только главный после синка. `merge_executor` стартует **только** из `delivered`. Если `head_sha` изменился после `approved` — назад в `awaiting_owner`, решение недействительно.

| Состояние | UI |
|---|---|
| `draft` | в списке запросов, апрува нет |
| `awaiting_owner` | колонка «На проверке», модалка, кнопки активны |
| `changes_requested` | карточка обратно «В работе», бейдж «на доработку», лента итераций |
| `approved` | «одобрено, ждём доставку на бокс»; «Смержить» уже не повторять |
| `delivered` | «доставлено, можно мержить» (ждёт исполнителя) |
| `merging` | спиннер, кнопки `disabled` |
| `merged` | тост, история; «Откатить» открывает запрос `mode: revert` |
| `rejected` | закрыт, в истории |
| `merge_failed` | ошибка + снова `awaiting_owner` |
| `reverted` | в истории откатов |
| смена `head_sha` | баннер «head изменился, решение сброшено» → `awaiting_owner` |

Колонка «На проверке» связана с «Запросы на мерж (N)»: мерж открывается из карточки, не только из шапки. Непересказанный отчёт берётся ссылками на `status/<bot>.json`.

## 4. Брейкпоинты, доступность, анимации

Сейчас в v6 `@media` нет — правила ниже **новые**.

| Ширина | Поведение |
|---|---|
| < 1280 | правая панель (тред) сворачивается; открывается выездом (`transform` 200 ms). Композер и чип «проснётся» остаются в панели. |
| 1280–1919 | как кадр 1440: рейл + чаты + сцена + тред 352. |
| ≥ 1920 | канбан шире (колонки не сжимаются < 220), орбита крупнее (до `max-width` больше 680), список — полная ширина рабочей зоны. |

Доступность: порядок фокуса по сетке; `:focus-visible` — кольцо 2 px accent; маскоты с `aria-label`; модалки — `role="dialog"`, `aria-modal`, ловушка Tab, Esc закрывает, фокус возвращается на открывшую кнопку; «Смержить» `disabled` озвучивает причину (CI / нет запроса). Контраст текста не ниже 4.5:1 (после правки `--faint`).

Анимации (§9, токены длительности): дыхание маскотов и кольцо-вспышка разбуженного (пауза, если вне экрана); пунктир от главного к адресату; карточка бота выезжает оверлеем; канбан — FLIP 200–300 ms; счётчик дотикивает; модалка мержа — fade + подъём снизу 200–300 ms; тост/бейдж; после «Смержить» — короткая галочка, после «На доработку» — карточка уходит в «В работе». Фон не анимировать, `blur` не анимировать. При `prefers-reduced-motion: reduce` — без анимаций, сразу конечное состояние.

### 4.1 Эффекты орбиты по референсу (`docs/UI_SPEC.md`, п. 1–4, 7)
- Связь: кривая Безье (SVG `path`) рисуется только во время обмена: появление через `stroke-dashoffset` за `--dur-slow`, после обмена гаснет за 600 ms. Постоянных линий нет.
- Частицы: 2–3 точки 4 px цвета отправителя бегут по `offset-path` от отправителя к адресату, один проход 1.2 s. Направление показывает, кто кому передаёт задачу.
- Активный бот: ореол своего цвета через `box-shadow`, цикл 1.6 s, пока бот работает. Заменяет прежнее кольцо-вспышку; вспышка остаётся только в момент пробуждения.
- Карточка задачи: всплывает рядом с работающим ботом (до 240 px: задача, прогресс, мини-аватары соисполнителей), плавает `translateY ±4px` за 3 s. Одновременно видно не больше 2 карточек, остальные показываются по наведению.
- Счётчики (экономия, пробуждения): докручиваются за 600 ms с `ease-out`, без скачков.
- Не берём: фоновые частицы и боке (фон не анимируем), режим «все сразу». Если проснулись все, показываем жёлтое предупреждение о расходе.
- Эффекты работают только в React, статичный `v6.html` остаётся эталоном для сравнения снимков. При `prefers-reduced-motion` анимаций нет, порог 55 fps по §12.

## 6. Мастер настройки (0.3.2)

Экран `/setup` собран на shadcn/ui (new-york) и Tailwind v4. Preflight не подключён: стили пульта в `App.css` не сбрасываются. Токены light/dark мастера висят на `.tb-wizard`, не на `:root`.

Каркас: шапка с заголовком «Настроить» (пустые состояния ведут сюда этой кнопкой), карточка, рейл 248px («Шаг N из 8», полоска, степпер), футер «Назад» / «Дальше». Ниже 720px рейл прячется, пары полей становятся столбцом. `prefers-reduced-motion` выключает анимации аватара и шеврона.

Шаг «Боты»: вкладки, кнопка-аватар 72px, поповер (превью 96px в `happy`, сетка 6×2, 10 свотчей и «Свой», «Без аватара»). Выбранный персонаж виден во вкладке и в сводке «Что запишем». В файл уходят `avatarId` и, если цвет не «свой», `avatarColor`.
