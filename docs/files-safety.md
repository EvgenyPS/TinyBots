# Запись файлов: что закрыто и что осталось

Режим `files` копирует `staging/` в папку проекта. Ниже — что делает код и какой риск сознательно остался.

## Что закрыто

- Путь проходит схему до диска. Хвостовые точки и пробелы сегмента отвергаются так же, как у `data_dir`. Двоеточие отвергается: на NTFS `note.txt:stream` — это альтернативный поток, а не файл.
- Манифест добавленных файлов пишется до цикла копирования. Обрыв процесса после манифеста и до копии всё равно знает, что удалять.
- Перед чтением файл открывается с `O_NOFOLLOW`, где флаг есть (Linux). Симлинк не читается.
- Перед `rename` путь проверяется ещё раз: родитель не симлинк, сам файл не симлинк. На Linux родитель открывается с `O_DIRECTORY|O_NOFOLLOW`.
- Сбой отката пишется в `fault` запроса и в `history`. Владелец видит текст. То же решение (`action` и `at`) повторно не запускается. Успешный переход снимает `fault`, иначе панель остаётся на старой причине.

## Остаточный риск

Node не даёт `openat` и `renameat`. Проверка и `rename` — два вызова по пути. Между ними другой процесс на той же машине может подменить каталог симлинком. На Windows флага `O_NOFOLLOW` нет, там остаётся `lstat` непосредственно перед записью: окно то же, только без дескриптора каталога.

Это локальный пульт одного владельца. Злоумышленник, который уже пишет в папку проекта между двумя системными вызовами, и так может менять файлы. Закрывать это отдельным томом или блокировкой каталога без решения владельца не стали.

Fine-grained токен GitHub без заголовка `X-OAuth-Scopes` и без объекта `permissions` вкладку Git не стартует. Так безопаснее, чем считать неизвестный токен доступным только для чтения.

## Инструменты бота

Denylist имён проверяется по запрошенной строке и по имени на диске (тот же `dev`/`ino` после `readdir`). В список входят `.git`, `node_modules`, `backups`, `staging`, `.env` и `.env.*`, ключи SSH, `*.pem`, `*.key`, `*.p12`, `*.pfx`, `*.jks`, `*.keystore`, `*.kdbx`, `*.crt`, `*.cer`, `*.der`, `*.p7b`, `*.ppk`, `*.asc`, `secring.gpg`, `pubring.*`, `trustdb.gpg` и каталоги учётных данных. Хвостовая точка и пробел отвергают сегмент целиком, их не срезают. Короткое имя вида `ENV~1` отвергается на любой ОС. Файл с `nlink > 1` не читается и не пишется. Доверяем nlink (libuv на Windows его заполняет). `ino` 0 чужое имя не подставляет.

Каноническое имя берётся с диска, чтобы поймать регистр, короткое имя Windows и символы, которые файловая система игнорирует. Сравнение идёт после NFC, в обоих регистрах.

Между повторной проверкой и `rename` по-прежнему нет `openat`. Крюк `beforeCommit` сверяет sha256 ещё раз, но окно между этой сверкой и `rename` остаётся.

## Безвозвратное удаление

Бот не удаляет файл, каталог `.git` и репозиторий. В списке инструментов нет операции удаления. `propose_patch` отвергает unified diff, который удаляет файл (`/dev/null`), переименовывает его, оставляет файл без непробельного текста или снимает строго больше половины строк. Порог `DELETE_LINE_RATIO_MAX` равен 0.5 и считается по убыли числа строк, а не по каждому минусу в хунке: замена строки на строку удалением не является. Пять строк из десяти ещё можно убрать, шесть — уже нет.

В режиме files снимок `proposals/<id>/backup/` читается при откате и не удаляется. Чистка по сроку и по числу записей трогает только отклонённые предложения и те, что не дошли до `applied`. Снимок применённого остаётся и после `reverted`.

В режиме git белый список не содержит команд, которые стирают объекты или переписывают историю. Единственное снятие ссылки — своя ветка `tinybots/proposal-<id>` при откате. Коммит после этого доступен по oid из json. `gc`, `reflog expire`, `filter-branch` и `push --delete` до процесса не доходят.

## Каталог proposals

Жёсткий потолок — 256 МиБ: новое предложение не пишется, если `занято + размер` больше предела. Снимки применённых правок сервер не удаляет сам, в том числе после отката. Когда каталог занимает 80% и больше, пульт показывает текст владельцу. Предложение при этом ещё принимается. Старые папки `proposals/` убирают вручную, иначе у потолка новые правки не сохранятся. На старте сервер снимает в `proposals/` только недописанные каталоги (`.<id>.partial` и папка без соседнего `<id>.json`): ссылку не открывает и папку проекта не трогает.
