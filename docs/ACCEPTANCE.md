# TinyBots: критерии приёмки

Автор: Тэст. Дата: 19.11.2026. Основа: `LAUNCHER_PLAN.md` (v2) и макет `v6.html`.
Каждый пункт проверяется тестом или ручным шагом и даёт pass или fail. Этап закрыт, когда все его пункты зелёные и владелец поставил ✅.
Тесты: юнит и интеграционные — vitest (server и web); e2e — Playwright (Chromium) на демо; визуальные — Playwright + pixelmatch против `v6-*.png`.

## B. Этап 1: пульт, бриф, записки

### B.1 Данные только из конфига
| ID | Критерий | Как проверяем |

## F. Протокол работы ботов и экономия токенов

Как бот ведёт себя в чате, лаунчер не контролирует. Поэтому проверяем две вещи: что генерирует лаунчер (автоматически) и как боты следуют скиллу (по выборке).

| ID | Критерий | Как проверяем |
|---|---|---|
| F1 | Бриф будит ровно одного бота (главного); остальные участники в нём не упомянуты | юнит на генератор: 0 упоминаний неглавных |
| F2 | Бриф ссылается на файлы, PR и SHA, а не вставляет содержимое: нет вставок > 3 строк кода или diff | юнит |
| F3 | Бриф «мержи <id>» — одна строка с id и ссылкой на запрос | юнит |
| F4 | Ответ бота по умолчанию ≤ 6 строк (`reply_limit: short`) | ручной аудит: 20 случайных ответов за неделю, ≥ 90% в лимите |
| F5 | На одну задачу не больше `max_wakes_per_task` пробуждений | аудит по истории чатов за неделю; цель — 0 нарушений |
| F6 | Нет сообщений «принял», «готово» без содержания: статус идёт через записку | аудит, цель — 0 |
| F7 | Боты на паузе не просыпаются | аудит + юнит на резолвер (B6) |
| F8 | Счётчик экономии подписан «оценка» и считается по формуле из docs | юнит на формулу, e2e на подсказку |
| F9 | Расход до и после: доля пробуждений на задачу и средняя длина ответа | baseline за неделю до внедрения скилла, повторный замер через неделю после; цель — минус 30% пробуждений (стартовая, решает владелец) |

## I. Инструменты папки и предложения правок

Оба ключа выключены по умолчанию: `project_tools: off` у своего бота и `allow_bot_tools: false` у проекта. `propose` ставится только явно, из мастера или карточки бота. У бота Grok поля `project_tools` нет, и запрос с ним отвергается. YAML руками для доступа не нужен. Ход без инструментов побайтно совпадает с прежним запросом: поля `tools` нет. Числа лимитов не сжимаются.
