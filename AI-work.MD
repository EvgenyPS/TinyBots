# AI-work

## Проект

TinyBots — локальный пульт над ботами. Репозиторий публичный: имена, пути и id задаются конфигом, в git лежат только вымышленные демо-данные. Сервер слушает `127.0.0.1`. Лицензия Apache-2.0.

Пульт строится из `config.yaml` и записок. Бриф собирается для главного чата (если такого бота нет — для главного проекта) и копируется в буфер или открывается ссылкой `grokbot://`. Мастер настройки пишет свой `config.yaml`, если файла ещё нет или он пустой. Запрос на мерж живёт в модалке: решение падает в `outbox/`, статус меняется после «Синхронизировать».

## Что в этом дереве

- npm workspaces: `packages/schema`, `apps/server` (Hono), `apps/web` (Vite + React, тёмная оболочка).
- `npm start` собирает страницу и открывает браузер. Нет своего `config.yaml` — корень открывает мастер. Демо-набор остаётся по `?demo=1`. Другой набор: `TINYBOTS_CONFIG=demo/sets/beta/config.yaml`.
- API: `/api/launcher`, `/api/projects`, `/api/roster`, `/api/chats`, `/api/notes`, `/api/tasks`, `/api/sync`, `/api/brief`, `/api/setup`, `/api/merge/decide`, `/api/sync/apply`, `/api/git`, `/api/files`, `/api/docs`. `/api/bots` читает `demo/bots.json`.
- Битый конфиг не роняет процесс: `422` с файлом, строкой и причиной. Пустой `config.yaml` открывает мастер. Время в зоне из конфига. Записка старше `stale_after_hours` — «устарело». Нет файла или он битый — «нет записки». Шапка: «данные на ЧЧ:ММ» по самому позднему `updated_at` в `sync/*.json`.
- Запись файла — временный файл и `rename`. На Windows `EPERM`/`EBUSY` повторяются несколько раз с паузой. Запись HTTP: `POST /api/setup`, `POST /api/merge/decide`, `POST /api/sync/apply`. Схема до диска, токен, порт через тот же `requestAllowed`. Нет Origin или он пустой — чтение пускает, запись нет. Строка `null` отклоняется и на чтении, и на записи. Новый конфиг публикуется через `link` после полного временного файла. Параллельные POST идут по очереди. `data_dir` не принимает `.git`, `package.json`, `node_modules`, `.github`, `scripts`, устройства Windows, хвостовые точки и пробелы, управляющие символы. Папка проекта может быть вне лаунчера. `/` и `/setup` отдают запрет фрейма.
- Host и Origin принимаются только с портом этого процесса. Чужой порт — 403.
- Бриф: один клик по задаче в колонке чата. Не больше 8 строк. Копирование кладёт в буфер текст превью. Ссылка `grokbot://app/v1/agent?id=<id>` только для id, который проходит формат. Рядом всегда «Если чат не открылся, откройте <имя> вручную». Пауза или нет главного — ошибка «Выберите главного», без превью.
- Очередь по умолчанию выключена (`delivery: clipboard`). Планировщик `queue` не пускает второй запуск в те же сутки зоны конфига. Файл очереди не пишется.
- Карточка бота — колонка справа от орбиты. Правого бота не накрывает.
- Мастер: семь шагов. Существующий непустой файл не меняется без подтверждения. `demo/` и `config.example.yaml` не перезаписываются. Папка без своего git показывает «вкладка Git будет скрыта». Свой git — это `.git` в папке и пустой `git rev-parse --show-prefix` (абсолютные пути на Windows не сравниваем).
- Пустые проекты, боты и записки: текст и кнопка «Настроить» → `/setup`.
- Запрос на мерж: кнопки в шапке неактивны без объектов. «Смержить», «На доработку», «Отклонить» и «Да, откатить» пишут outbox. Синк проводит автомат. Мерж GitHub — мок. Вкладка Git читает API отдельным `fetch` и токеном только для чтения. Режим files пишет манифест до копирования, перед rename ещё раз смотрит симлинк, сбой отката кладёт в `fault`. В список файлов не входят `.git`, `backups.`, хвостовые точки и пробелы, двоеточие, устройства Windows и пустые сегменты. Подробности: `docs/merge-flow.md`, остаток гонки: `docs/files-safety.md`.
- Вкладки «Файлы», «Git» и «Документация». Проект без git прячет Git. Markdown рисуется блоками, без сырого HTML. Движение только `transform`/`opacity`, 150–300 мс. Ручной чеклист: `docs/v1-manual.md`.
- `npm test` — vitest. `npm run e2e` сам собирает страницу и запускает Playwright 1.65. CI: Node 20/24, Ubuntu и Windows. Lighthouse и fps — только Ubuntu и Node 24.
