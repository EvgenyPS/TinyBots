# AI-work

## Проект

TinyBots — локальный пульт над ботами. Репозиторий публичный: имена, пути и id задаются конфигом, в git лежат только вымышленные демо-данные. Сервер слушает `127.0.0.1`. Лицензия Apache-2.0.

Пульт строится из `config.yaml` и записок. Бриф собирается для главного чата (если такого бота нет — для главного проекта) и копируется в буфер или открывается ссылкой `grokbot://`. Мастер настройки пишет свой `config.yaml`, если файла ещё нет или он пустой. Запрос на мерж живёт в модалке: решение падает в `outbox/`, статус меняется после «Синхронизировать».

## Разведка Tauri 2

- Каркас окна в `apps/desktop`. Иконка: `apps/desktop/icons/app.ico`. Версия пакетов не поднималась.
- Сервер для окна — Node SEA sidecar. `@napi-rs/keyring` `.node` кладётся рядом с exe и открывается через `dlopen`. Обычный `node` по-прежнему ходит в пакет дочерним процессом.
- Окно само запускает sidecar и гасит его при закрытии. Занятый 8787 — отдельная страница, без подключения к чужому процессу.
- Защита: только `127.0.0.1`; Origin `http://tauri.localhost` ровно один; Host десктопа `127.0.0.1:8787` и `localhost:8787`; токен 32 байта на запуск, в памяти, `timingSafeEqual`; `/api/*` без токена — 401; `npm start` получает `--browser` аргументом. Ответы API не отдают значение ключа.
- CI: job `desktop` на `windows-latest` собирает NSIS и пишет размер в лог. Прежние проверки на месте.
- Токен в окно попадает только при `location.origin === "http://tauri.localhost"`. Внешний `http`/`https` отменяется и открывается из Rust через `tauri-plugin-opener`. Странице это право не выдано.
- Окно больше не ждёт sidecar в `setup`. Сначала экран загрузки, sidecar в фоне. Готовность — только строка `TinyBots: http://127.0.0.1:8787` в stdout нашего процесса. Токен на порт до этой строки не уходит. Таймаут 15 с не гасит уже живой процесс. На Windows sidecar стартует с `CREATE_NO_WINDOW`. Журнал: `%LOCALAPPDATA%\app.tinybots.desktop\logs`, токен вырезается даже на границе кусков.
- Данные окна: каталог Tauri `app.tinybots.desktop` (на Windows `%APPDATA%\app.tinybots.desktop`), аргумент `--data-dir`. Пустой `bots.json` создаётся один раз. Существующий и битый файл не затираются. Обновление установщика эту папку не трогает. `--browser` и dev читают `demo/bots.json` как раньше.
- SEA собран как CommonJS: у Node встроенный ESM в single executable не стартует (`embedderRunCjs`). `import.meta.url` в этом бандле пустой, `createRequire` берёт `process.execPath`. На Linux модуль keyring открывается, запись в связку не проходит без DBus — та же ошибка, что у обычного `node`.

## Что в этом дереве

- npm workspaces: `packages/schema`, `apps/server` (Hono), `apps/web` (Vite + React, тёмная оболочка).
- `npm start` собирает страницу и открывает браузер. Нет своего `config.yaml` — корень открывает мастер. Демо-набор остаётся по `?demo=1`. Другой набор: `TINYBOTS_CONFIG=demo/sets/beta/config.yaml`.
- API: `/api/launcher`, `/api/projects`, `/api/roster`, `/api/chats`, `/api/notes`, `/api/tasks`, `/api/sync`, `/api/brief`, `/api/setup`, `/api/merge/decide`, `/api/sync/apply`, `/api/git`, `/api/files`, `/api/docs`. `/api/bots` читает `demo/bots.json`.
- Битый конфиг не роняет процесс: `422` с файлом, строкой и причиной. Пустой `config.yaml` открывает мастер. Время в зоне из конфига. Записка старше `stale_after_hours` — «устарело». Нет файла или он битый — «нет записки». Шапка: «данные на ЧЧ:ММ» по самому позднему `updated_at` в `sync/*.json`.
- Запись файла — временный файл и `rename`. На Windows `EPERM`/`EBUSY` повторяются несколько раз с паузой. Запись HTTP: `POST /api/setup`, `POST /api/merge/decide`, `POST /api/sync/apply`. Схема до диска, токен, порт через тот же `requestAllowed`. Нет Origin или он пустой — чтение пускает, запись нет. Строка `null` отклоняется и на чтении, и на записи. Новый конфиг публикуется через `link` после полного временного файла. Параллельные POST идут по очереди. `data_dir` не принимает `.git`, `package.json`, `node_modules`, `.github`, `scripts`, устройства Windows, хвостовые точки и пробелы, управляющие символы. Папка проекта может быть вне лаунчера. `/` и `/setup` отдают запрет фрейма.
- Host и Origin принимаются только с портом этого процесса. Чужой порт — 403.
- Бриф: один клик по задаче в колонке чата. Не больше 8 строк. Копирование кладёт в буфер текст превью. Ссылка `grokbot://app/v1/agent?id=<id>` только для id, который проходит формат. Рядом всегда «Если чат не открылся, откройте <имя> вручную». Пауза или нет главного — ошибка «Выберите главного», без превью.
- Очередь по умолчанию выключена (`delivery: clipboard`). Планировщик `queue` не пускает второй запуск в те же сутки зоны конфига. Файл очереди не пишется.
- Карточка бота — колонка справа от орбиты. Правого бота не накрывает.
- Мастер: семь шагов. Существующий непустой файл не меняется без подтверждения. `demo/` и `config.example.yaml` не перезаписываются. Папка без своего git показывает «вкладка Git будет скрыта». Свой git — это `.git` в папке и пустой `git rev-parse --show-prefix` (абсолютные пути на Windows не сравниваем).
- Пустые проекты, боты и записки: текст и кнопка «Настроить» → `/setup`.
- Запрос на мерж: кнопки в шапке неактивны без объектов. «Смержить», «На доработку», «Отклонить» и «Да, откатить» пишут outbox. Синк проводит автомат. Мерж GitHub — мок. Вкладка Git читает API отдельным `fetch` и токеном только для чтения. Режим files пишет манифест до копирования, перед rename ещё раз смотрит симлинк, сбой отката кладёт в `fault`. В список файлов не входят `.git`, `backups.`, хвостовые точки и пробелы, двоеточие, устройства Windows и пустые сегменты. Подробности: `docs/merge-flow.md`, остаток гонки: `docs/files-safety.md`.
- Вкладки «Файлы», «Git» и «Документация». Проект без git прячет Git. `repo:status` — запись, вкладка не стартует. `Sec-Fetch-Site: cross-site` на `/api/git` — 403 до GitHub. Документы только `*.md`. Markdown рисуется блоками, без сырого HTML. Движение только `transform`/`opacity`, 150–300 мс. Успешный переход мержа снимает `fault`. Ручной чеклист: `docs/v1-manual.md`.
- `npm test` — vitest. `npm run e2e` сам собирает страницу и запускает Playwright 1.65. CI: Node 20/24, Ubuntu и Windows. Lighthouse и fps — только Ubuntu и Node 24.

## Свои боты на ключах (H1–H15)

- В конфиге два вида ботов: Grok Bot как раньше и свой API-бот (инструкции, провайдер, модель, `base_url`, `api_key_env`). Значение ключа только в `.env`.
- Вызов OpenAI-совместимого `chat/completions` через `fetch`, с проверкой адреса, таймаутом и повторами. Чат в пульте, бриф уходит сам, записка пишется по схеме и не закрывает задачу.
- `Sec-Fetch-Site: same-site` и `cross-site` на `/api` отвечают 403 до сети.
- Демо-набор `demo/sets/api-keys`: Нора и Бит. Мок локальный, настоящих ключей нет.
- Проверено локально: `npx tsc -b`, vitest 137, e2e 29, `check:forbidden`, `check:motion`, gitleaks.
- После ревью: чтение тела модели в try, CSRF и пауза чата покрыты тестами, ключ в реплике и ответе прячется. Пресет deepseek/qwen подставляет официальный HTTPS. IPv6 со встроенным IPv4 отсекается.

## Шаблоны инструкций и id с -bot (0.3.3)

- На шаге «Боты» у своего API-бота над инструкциями список шаблонов. Текст подставляется, ручную правку смена шаблона не затирает без вопроса в карточке. «Своя» оставляет уже написанное.
- Новый id бота: транслит имени + `-bot`. Ручной ввод без суффикса дополняется на blur и перед проверкой шага. Двойного `-bot` нет. Автодубль получает номер (`revik2-bot`), ручной дубль — ошибка у поля. Схема, сервер и уже лежащие id не менялись. Id проекта и чата без суффикса.

## Мастер на shadcn и аватары (0.3.2)

- Tailwind v4 подключён плагином Vite, preflight выключен. CSS мастера грузится отдельным куском, токены на `.tb-wizard`.
- Шаги мастера на компонентах `apps/web/src/components/ui`. Select и «Дополнительно» остались нативными: e2e зовёт `selectOption` и читает `HTMLDetailsElement.open`.
- Аватары v3 лежат в `apps/web/src/avatars`. `<BotAvatar>` вставляет SVG инлайном и один раз вызывает `followPointer()`.
- В схеме бота необязательные `avatarId` и `avatarColor`. Поле `avatar` (путь) не трогали.

## Мастер, шаг «Боты» (0.3.1)

- Свой API-бот: модель из списка (DeepSeek `deepseek-chat` / `deepseek-reasoner`, Qwen — текстовые модели DashScope `qwen4-max`, `qwen3.7-plus`, `qwen3.8-flash`). Пункт «своя» открывает ручной ввод.
- Имя ключа (`DEEPSEEK_API_KEY` / `QWEN_API_KEY`) и `base_url` подставляются сами. Адрес берётся из `LLM_PRESET_BASE_URL` в схеме, второй список адресов не заведён.
- Ручная правка не затирается сменой модели. Смена провайдера обновляет только нетронутые поля.
- Id, имя ключа и `base_url` лежат в «Дополнительно». Если валидация ругается на них, блок раскрывается. Имя и роль, провайдер и модель — по два в ряд, на узком экране столбцом.
- Схема конфига и сервер не менялись.
